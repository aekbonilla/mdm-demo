What Is MDM?

Mobile Device Management is a policy enforcement layer between an organization and the devices its users carry.


Core capabilities:

  • Remote lock & wipe
  • Enforce encryption & passcode
  • App allow/block lists
  • VPN & Wi-Fi profile push
  • Certificate management
  • Compliance monitoring

Tools we use today:


Android Headwind MDM
Open-source · Docker · localhost:8080


MDM protocol on iOS is Apple's proprietary APNs-based protocol. Android uses its own Device Policy Manager API. Both are standardised — Headwind and NanoMDM implement the open specs.

Demo 5 — Compliance Dashboard

PROBLEM WITHOUT MDM: IT has no visibility. Devices may be unencrypted, running outdated OS, or have malicious apps — and nobody knows.
MDM VISIBILITY:

Headwind MDM → Devices tab shows:

  • Online / offline status
  • Last sync time
  • Policy compliance (green/red)
  • OS version + security patch
  • Installed app list
  • Storage encryption state

What a compliance violation looks like:

  • ⚠ PIN strength below policy
  • ⚠ Unapproved app installed
  • ⚠ OS not updated
  • ⚠ Device not seen in 7 days
  • ✓ Encryption enabled
  • ✓ All policies applied
Live: open localhost:8080, go to Devices. Point out the compliance column. Show the device detail page — expand it to see all the enrolled device info. This is what separates MDM from "asking users to configure their phones."

Rogue AP / MITM Always-on VPN profile enforced by MDM mitmproxy → vpn
Stolen device Remote lock + FDE + remote wipe HMDM admin panel
Malicious / over-privileged app App blocklist + permission restrictions xcrun simctl privacy
Data leakage (managed→personal) allowOpenFromManagedToUnmanaged: false mobileconfig

This is the closing summary. Each row maps an attack to a specific MDM control and the tool we used to demonstrate it. Emphasize: MDM does NOT prevent all attacks, but it massively raises the cost of attack and reduces the blast radius.

Key Takeaways

🔐 MDM shifts security from user responsibility to policy enforcement.
Users don't need to "remember" to turn on encryption — MDM won't let them turn it off.


🌐 Always-on VPN is the primary defence against network-layer attacks.
A rogue AP is useless if every connection is tunnelled before it hits the AP.


👁️ Visibility is a security control.
You cannot protect what you cannot see. Compliance dashboards are threat detection tools.


🔓 MDM is defeated by physical access + no FDE, social engineering, and zero-days.
It is one layer. Combine with EDR, UEBA, and user training.

Wrap up in under 30 seconds. Leave time for questions. If asked about zero-days: MDM can enforce update policies to shrink the patch window, but a fresh zero-day beats MDM until a patch is deployed.
